This  provides a comprehensive guide to essential **command-line networking utilities** that every network administrator and IT professional should master. It covers ping, traceroute, nslookup/dig, tcpdump, netstat, ipconfig/ifconfig, and arp, along with the protocols they use and how to interpret their output.



---

### Command Line Networking Utilities Cheat Sheet

This guide covers the most common command‑line tools for testing connectivity, tracing paths, resolving names, capturing packets, viewing statistics, and inspecting IP/MAC configurations.

---

#### ping (Test Reachability)

| Aspect | Description |
| :--- | :--- |
| **Protocol** | ICMP (Echo Request / Echo Reply). |
| **What it tests** | Whether a destination host is reachable and how long it takes (round‑trip time). |
| **Common output** | `64 bytes from 1.1.1.1: icmp_seq=0 ttl=56 time=12.3 ms` |
| **Failure indication** | `Request timed out` or `Destination host unreachable`. |
| **Stop (continuous ping)** | `Ctrl + C` (shows summary statistics). |

**Basic Syntax:**

| OS | Command | Notes |
| :--- | :--- | :--- |
| Windows | `ping 8.8.8.8` | Sends 4 pings by default. |
| Linux / macOS | `ping 8.8.8.8` | Sends continuously until `Ctrl + C`. |

**Troubleshooting order (ping):**
1. `ping 127.0.0.1` – verify local TCP/IP stack.
2. `ping <own IP>` – verify NIC driver.
3. `ping <default gateway>` – verify local network connectivity.
4. `ping <remote IP>` – verify routing and remote reachability.

#### traceroute (Path Discovery)

| Aspect | Description |
| :--- | :--- |
| **Protocol** | ICMP (Type 11 – Time Exceeded) + ICMP Echo Request / UDP (varies by OS). |
| **How it works** | Sends packets with increasing TTL (1, 2, 3…). Each router along the path decrements TTL; when TTL=0, router returns ICMP Time Exceeded with its IP address. |
| **Output** | List of hop IP addresses and round‑trip times (three probes per hop by default). |
| **Asterisk (`*`)** | No response within timeout (likely ICMP filtering / firewall). |

| OS | Command |
| :--- | :--- |
| Windows | `tracert 8.8.8.8` |
| Linux / macOS | `traceroute 8.8.8.8` (may need to install with `brew` or `apt`). |

**Example Output (from video):**
```
1  10.1.10.1 (2 ms, 2 ms, 2 ms)
2  96.120.58.137 (10 ms, 11 ms, 10 ms)
3  ...
10 8.8.8.8 (15 ms, 15 ms, 16 ms)
```

**Use Cases:**
- Identify where packets are being delayed or dropped.
- Compare baseline path against current path during an outage.

#### nslookup and dig (DNS Query)

| Utility | OS | Status | Use Case |
| :--- | :--- | :--- | :--- |
| **nslookup** | Windows, Linux, macOS | **Deprecated** (but still works) | Simple DNS queries (A, AAAA, MX, TXT). |
| **dig** | Linux, macOS (native), Windows (third‑party) | Preferred (not deprecated) | Detailed DNS output (TTL, answer section, query time, etc.). |

**nslookup example:**
```
nslookup www.professormesser.com
Server:  1.1.1.1
Address: 1.1.1.1#53

Non-authoritative answer:
Name:    www.professormesser.com
Address: 104.22.73.108
Address: 104.22.72.108
Address: 172.67.41.114
```

**dig example:**
```
dig www.professormesser.com A
...
;; ANSWER SECTION:
www.professormesser.com. 300 IN A 172.67.41.114
www.professormesser.com. 300 IN A 104.22.73.108
www.professormesser.com. 300 IN A 104.22.72.108
```

**Note:** Multiple addresses indicate redundancy (load balancing or failover).

**Troubleshooting DNS:**
- Use `nslookup` or `dig` to check if DNS resolution works.
- Query specific DNS servers: `dig @8.8.8.8 www.example.com`.

#### tcpdump (Packet Capture)

| Aspect | Description |
| :--- | :--- |
| **Platforms** | Linux, macOS (native); Windows (WinDump or Wireshark). |
| **Output format** | `pcap` (packet capture) – readable by Wireshark. |
| **Filters** | Use `host`, `port`, `proto`, `and` / `or` to reduce noise. |
| **Save to file** | `-w capture.pcap` |
| **Read from file** | `-r capture.pcap` |

**Common tcpdump examples:**

| Task | Command |
| :--- | :--- |
| Capture all traffic on interface | `tcpdump -i eth0` |
| Capture to file | `tcpdump -i eth0 -w capture.pcap` |
| Capture only ICMP (ping) | `tcpdump -i eth0 icmp` |
| Capture only on port 53 (DNS) | `tcpdump -i eth0 port 53` |
| Capture from/to specific host | `tcpdump -i eth0 host 10.1.10.234` |

**Use Cases:**
- Deep packet inspection (retransmissions, window size, application delays).
- Security analysis (unusual traffic, rogue devices).
- Troubleshooting when ping/traceroute are insufficient.

#### netstat (Network Statistics)

| Aspect | Description |
| :--- | :--- |
| **What it shows** | Active connections (inbound and outbound), listening ports, routing table, interface statistics. |
| **Platforms** | Windows, Linux, macOS. |

**Common netstat options (Windows):**

| Option | Description |
| :--- | :--- |
| `netstat -a` | Show all active connections and listening ports. |
| `netstat -b` | Show the executable (binary) that created the connection (Windows only, requires admin). |
| `netstat -n` | Show IP addresses and ports numerically (no DNS resolution). |
| `netstat -r` | Show routing table. |
| `netstat -e` | Show Ethernet (interface) statistics. |

**Linux / macOS equivalents:**
- `netstat -tunap` – TCP (`-t`), UDP (`-u`), numeric (`-n`), listening/established (`-a`), program (`-p`).
- `ss` (modern replacement for netstat on Linux).

**Example Output (Windows netstat -b):**
```
chrome.exe     TCP  10.1.1.102:54321   192.0.2.10:443   ESTABLISHED
```

**Use Cases:**
- See what services are listening on a device.
- Identify which application is using a particular port.
- Detect unexpected outbound connections.

#### ipconfig / ifconfig / ip (IP Configuration)

| OS | Command | Description |
| :--- | :--- | :--- |
| Windows | `ipconfig` | Basic IPv4/IPv6, subnet mask, default gateway. |
| Windows | `ipconfig /all` | Detailed: MAC address, DHCP lease, DNS servers. |
| Linux / macOS (legacy) | `ifconfig` | Interface configuration (deprecated on some Linux distros). |
| Linux (modern) | `ip addr` or `ip address` | Replacement for ifconfig. |

**ipconfig /all** (Windows) shows:
- Hostname, MAC address (physical address), IPv4 address, subnet mask, default gateway, DHCP server, DNS server, lease timers.

**ip addr show** (Linux) shows:
- MAC address (link/ether), IPv4 and IPv6 addresses, interface state.

**Use when:** You sit down at an unknown device and need to know its IP address, gateway, or MAC address.

#### arp (Address Resolution Protocol Cache)

| Aspect | Description |
| :--- | :--- |
| **What it shows** | Mapping between IP addresses and MAC addresses on the local subnet (layer 2 to layer 3 resolution). |
| **Platforms** | Windows, Linux, macOS. |
| **Command** | `arp -a` (display cache). |

**How it works (brief):**
1. Device needs MAC address for an IP on the same subnet.
2. Sends ARP broadcast ("Who has 10.1.10.234?").
3. Owner replies with its MAC address.
4. Entry stored in ARP cache (typically a few minutes).

**Use case:** When you find a duplicate IP address or want to verify a device's MAC address without logging into the switch.

**Example (from video):**
```
arp -a
10.1.10.234    00-1A-2B-3C-4D-5E    dynamic
10.1.10.1      aa-bb-cc-dd-ee-ff    dynamic
```

**Tip:** If a target IP is not in the ARP cache, send a ping to that IP first (this triggers an ARP request), then run `arp -a`.

#### Quick Reference: Command by Use Case

| Use Case | Command |
| :--- | :--- |
| Is the host reachable? | `ping <IP>` |
| What path does traffic take? | `tracert` (Windows) / `traceroute` (Linux/macOS) |
| What is my IP address? | `ipconfig` (Windows) / `ip addr` (Linux) / `ifconfig` (macOS) |
| What is my MAC address? | `ipconfig /all` or `arp -a` (for neighbours) |
| Does DNS resolve correctly? | `nslookup <name>` or `dig <name>` |
| What services are listening? | `netstat -an` |
| Which program is using a port? | `netstat -b` (Windows) / `netstat -tunap` (Linux) |
| Capture live traffic? | `tcpdump -i eth0` |
| Resolve IP to MAC? | `arp -a` |

---

#### Key Takeaways

| Takeaway | Explanation |
| :--- | :--- |
| **ping tests basic reachability** | First tool to use but can be blocked by firewalls. |
| **traceroute maps the path** | Shows each router hop; asterisk (`*`) often means ICMP filtering. |
| **nslookup / dig test DNS** | Essential for name resolution problems. |
| **tcpdump (or Wireshark) gives deep insight** | See the actual packets – delays, retransmissions, application data. |
| **netstat shows active connections** | Know who is talking to whom and which programs are involved. |
| **ipconfig / ifconfig / ip addr** | Find your own IP and MAC address. |
| **arp -a maps IP to MAC** | Useful for tracking down duplicate IPs or verifying devices on the local subnet. |
