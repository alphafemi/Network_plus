### Routing and IP Addressing Troubleshooting Cheat Sheet

This guide covers common layer‑3 problems, routing table diagnostics, default routes, DHCP issues, and duplicate IP address detection.

---

#### Routing Table Basics

| Aspect | Description |
| :--- | :--- |
| **Purpose** | Determines the best next hop for forwarding traffic through a router. |
| **What it contains** | Directly connected networks, static routes, dynamic routes (OSPF, EIGRP, RIP), and default route. |
| **Missing route → dropped traffic** | If no route matches the destination, the router drops the packet and may send an **ICMP Destination Unreachable (Host Unreachable)** message back to the source. |

**Troubleshooting Rule:** You must check the routing table of **every router along the path** – not only the forward path, but also the **return path** (back to the original source).

---

#### Default Route (Gateway of Last Resort)

| Aspect | Description |
| :--- | :--- |
| **Definition** | A catch‑all route used when no other route matches the destination. |
| **Destination** | Usually `0.0.0.0/0` (matches every possible IPv4 address). |
| **Configuration** | Added as a static route (e.g., `ip route 0.0.0.0 0.0.0.0 10.10.50.2`). |
| **Router message when not set** | `Gateway of last resort is not set`. |

**Example (from video):**

| Route Type | Destination | Next Hop / Interface |
| :--- | :--- | :--- |
| Directly connected | 10.10.10.0/24 | F0/0 |
| Directly connected | 10.10.40.0/24 | F0/1 |
| Directly connected | 10.10.50.0/24 | F0/2 |
| Static | 10.10.20.0/24 | 10.10.40.2 |
| Learned (RIP) | 10.10.30.0/24 | 10.10.50.2 |
| **Default (gateway of last resort)** | **0.0.0.0/0** | **10.10.50.2** |

**Result:** Any traffic not matching the first five routes is sent out interface to `10.10.50.2`.

#### DHCP Failure and APIPA

| Problem | Symptom | Cause | Solution |
| :--- | :--- | :--- | :--- |
| **Address pool exhausted** | Device gets **APIPA address** (169.254.x.x) instead of a routable IP. | No available addresses in DHCP scope. | Increase pool size, reduce lease time, or add more scopes. |
| **APIPA** | Device assigns itself a link‑local address (169.254.0.0/16). | DHCP server unreachable or no addresses left. | APIPA is **non‑routable** – cannot reach other subnets or internet. |

**Mitigation for high‑turnover networks:**
- **Decrease lease time** (e.g., from 8 days to 1 day) so addresses return to the pool faster.
- Use **IP Address Management (IPAM)** to monitor pool utilisation centrally.

#### Incorrect IP Configuration

| Symptom | Possible Cause | Troubleshooting |
| :--- | :--- | :--- |
| Wrong IP address, subnet mask, or default gateway. | Misconfigured DHCP scope, manual misconfiguration, wrong VLAN. | Compare with other working devices on the same network (check their IP/subnet/gateway). |
| No route to remote networks. | Default gateway missing or wrong. | Ping default gateway; if that works, traceroute beyond it. |

**Diagnostic Steps:**

| Step | Action |
| :--- | :--- |
| 1 | Ping `127.0.0.1` (loopback) – verify local TCP/IP stack. |
| 2 | Ping own assigned IP address – verify NIC driver. |
| 3 | Ping default gateway – verify local network connectivity. |
| 4 | Ping an IP address beyond the gateway – verify routing. |
| 5 | Use `traceroute` to see where packets stop. |

#### Duplicate IP Addresses

| Cause | Description |
| :--- | :--- |
| **Static vs. DHCP conflict** | A manually configured device uses an IP that is also in a DHCP pool. |
| **Overlapping DHCP scopes** | Two DHCP servers both configured to hand out the same range. |
| **Rogue DHCP server** | Unauthorised device (e.g., a consumer router) handing out addresses. |

**Symptoms:**
- Modern OS: Error message upon connection (duplicate address detected).
- Older OS: Two devices “fight” over the address; MAC table on switch may flip-flop.

**Troubleshooting Flow for Duplicate IP:**

| Step | Action |
| :--- | :--- |
| 1 | Ping the IP address **before** statically assigning it (if you get a reply, it is already in use). |
| 2 | If ping reply received, examine the **ARP table** (`arp -a` on Windows/Linux) to get the duplicate device’s MAC address. |
| 3 | Look up the MAC address in **switch MAC address table** (`show mac address-table`) to find the switch port. |
| 4 | Trace the cable from that port to locate the physical device. |
| 5 | If two DHCP servers are the cause, perform a **packet capture** on DHCP traffic to see which server is offering which addresses. |

#### Quick Troubleshooting Reference

| Problem | Most Common Cause | Immediate Test |
| :--- | :--- | :--- |
| Cannot reach remote network | Missing default gateway or wrong gateway IP. | `ping <gateway>` → if fails, check gateway IP in DHCP or manual config. |
| Device gets 169.254.x.x | DHCP failure (server down, pool exhausted). | Check DHCP server status; increase scope or reduce lease time. |
| Intermittent connectivity to one host | Duplicate IP address. | Ping IP from a third device; if intermittent, check for duplicate. |
| One‑way connectivity (can ping out but cannot be pinged back) | Return path missing from routing table on far side. | Check routing table of remote router for route back to source subnet. |
| Packet loss at a specific hop | Interface error, ACL, or routing loop. | `traceroute` to identify hop; check interface counters, ACLs, routing table. |

#### Common Commands for Troubleshooting

| Task | Command (Cisco / Linux / Windows) |
| :--- | :--- |
| Show routing table | `show ip route` / `ip route` / `route print` |
| Add default route (Cisco) | `ip route 0.0.0.0 0.0.0.0 <next‑hop>` |
| Ping | `ping <IP>` |
| Traceroute | `traceroute` / `tracert` |
| Show ARP table | `show arp` / `arp -a` |
| Show switch MAC table | `show mac address-table` |
| Packet capture (DHCP) | `tcpdump -i eth0 port 67 or port 68` / Wireshark |

---

#### Key Takeaways

| Takeaway | Explanation |
| :--- | :--- |
| **Routing table must have a match** | No match → packet dropped (often with ICMP unreachable). |
| **Gateway of last resort = 0.0.0.0/0** | A catch‑all default route for everything not explicitly listed. |
| **APIPA = DHCP failed** | 169.254.x.x addresses are non‑routable; check DHCP server. |
| **Duplicate IP detection** | Ping before static assignment; use ARP + switch MAC table to locate the conflict. |
| **Check return path** | One‑way connectivity often means the remote router lacks a route back to your subnet. |
| **Packet captures help with DHCP conflicts** | See which server is offering which address. |
