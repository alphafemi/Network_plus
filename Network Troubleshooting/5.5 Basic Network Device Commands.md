This  provides a practical guide to essential **command-line interface (CLI) commands** commonly used on network devices (switches and routers) from vendors like Cisco. It focuses on the key `show` commands for viewing operational information, such as MAC address tables, routing tables, interface status, configurations, ARP caches, VLAN assignments, and PoE power budgets.


---

### Common CLI Commands on Network Devices Cheat Sheet

This guide covers the fundamental `show` commands for inspecting the state of switches and routers.

---

#### Core `show` Commands

| Command | Purpose | Key Information Provided |
| :--- | :--- | :--- |
| `show mac-address-table` | Display the switch's MAC address table (CAM table). | MAC addresses, associated VLANs, and output ports. |
| `show route` (or `show ip route`) | Display the routing table (Layer 3). | Destination networks, next‑hop IP addresses, outgoing interfaces, route sources (e.g., connected, static, OSPF, RIP). |
| `show interface` | Display interface status and statistics. | Link status (up/down), speed, duplex, MTU, errors (CRC, drops), input/output rates. |
| `show config` (or `show running-config`) | Display the current active configuration. | Complete device configuration (interfaces, VLANs, routing protocols, passwords). |
| `show arp` | Display the ARP cache. | IP address to MAC address mappings, associated interface. |
| `show vlan` | Display VLAN assignments. | VLAN IDs, names, and which interfaces are members of each VLAN. |
| `show power` (or PoE‑specific commands) | Display Power over Ethernet status. | Per‑port PoE status (on/off), power consumption (watts), total power budget, remaining power. |

---

#### Show Mac‑Address‑Table

| Aspect | Description |
| :--- | :--- |
| **Use case** | Troubleshoot forwarding issues (unicast flooding when a MAC is not in the table); verify learned MAC addresses; check table size. |
| **Typical output columns** | VLAN, MAC address, Type (dynamic/static), Port/Interface. |

**Example (Cisco):**
```
Switch# show mac-address-table
VLAN    MAC Address       Type        Port
----    -----------       ----        ----
  1     0050.56b3.1234    DYNAMIC     Gi1/0/1
  1     0050.56b3.5678    DYNAMIC     Gi1/0/2
```

**Note:** If a MAC is not in the table → the switch will flood frames to all ports in that VLAN (unless blocked by STP).

#### Show Route (Routing Table)

| Aspect | Description |
| :--- | :--- |
| **Use case** | Verify route existence, next‑hop, interface; trace end‑to‑end path. |
| **Common route sources (Cisco)** | `C` = Connected, `S` = Static, `R` = RIP, `O` = OSPF, `D` = EIGRP, `B` = BGP. |

**Example (Cisco):**
```
Router# show ip route
Codes: C - connected, S - static, R - RIP, O - OSPF

C    10.10.10.0/24 is directly connected, FastEthernet0/0
S    192.168.1.0/24 [1/0] via 10.10.10.1
R    172.16.0.0/16 [120/1] via 10.10.20.2, Serial3/0
```

**Troubleshooting tip:** Follow the path by identifying the next‑hop for a destination, then checking the next router's routing table, and so on.

#### Show Interface

| Aspect | Description |
| :--- | :--- |
| **Use case** | Check link status, speed/duplex mismatches, physical errors (CRC, giants, runts, collisions). |

**Key output lines (Cisco):**
```
FastEthernet0/0 is up, line protocol is up
  Hardware is ... address ...
  MTU 1500 bytes, BW 100000 Kbit, DLY 100 usec
  Full-duplex, 100Mb/s, media type is RJ45
  Input queue: 0/75/0/0 (size/max/drops/flushes)
  5 minute input rate 1000 bits/sec, 2 packets/sec
  0 input errors, 0 CRC, 0 frame, 0 overrun
  0 output errors, 0 collisions
```

**Check first line:** `[interface] is up, line protocol is up`
- `up / down` → physical layer issue (cable, far‑end powered off).
- `up / down (line protocol down)` → often no signal (cable unplugged).
- `administratively down` → interface disabled by admin (`shutdown`).

**Look at the end:** `input errors`, `CRC`, `collisions`, `output errors` – increasing counters indicate cable, duplex mismatch, or hardware problems.

#### Show Config (Running Configuration)

| Aspect | Description |
| :--- | :--- |
| **Use case** | View the **active** configuration (what is currently running on the device). |
| **Typical command** | `show running-config` (many vendors) ; also `show config` on some older devices. |
| **Output** | Full text configuration (hostname, passwords, interface IPs, VLANs, routing protocol settings). |

**Example (Cisco):**
```
Router# show running-config
Building configuration...
Current configuration : 830 bytes
!
hostname Router1
!
interface FastEthernet0/0
 ip address 10.10.10.1 255.255.255.0
 no shutdown
...
```

**Related commands:**
- `show startup-config` – configuration saved in NVRAM (used at boot).
- `copy running-config startup-config` – save changes so they persist after reboot.

#### Show ARP

| Aspect | Description |
| :--- | :--- |
| **Use case** | Verify MAC‑to‑IP mapping on the router/switch; detect duplicate IP addresses. |

**Example (Cisco):**
```
Router# show arp
Protocol  Address          Hardware (MAC)       Interface
Internet  10.10.10.1       aaaa.bbbb.cccc        FastEthernet0/0
Internet  10.10.10.2       1111.2222.3333        FastEthernet0/0
```

**Note:** ARP entries have a timeout (typically ~4 hours on Cisco routers); cleared when the mapping ages out.

#### Show VLAN

| Aspect | Description |
| :--- | :--- |
| **Use case** | Check which VLAN is assigned to which access port; verify native VLAN on trunks; identify unused VLANs. |

**Example (Cisco):**
```
Switch# show vlan
VLAN Name         Status    Ports
1    default      active    Gi1/0/1, Gi1/0/2, Gi1/0/3...
10   Sales        active    Gi1/0/4, Gi1/0/5
20   Engineering  active    Gi1/0/6, Gi1/0/7
```

**Troubleshooting tip:** If a device cannot communicate with others on the same subnet, check whether its switch port is in the wrong VLAN.

#### Show Power (PoE)

| Aspect | Description |
| :--- | :--- |
| **Use case** | Monitor PoE power consumption; verify enough remaining power for new devices. |

**Example (Cisco):**
```
Switch# show power inline
Interface  Admin  Oper   Power   (Watts)
Gi1/0/1    auto   on     15.4
Gi1/0/2    auto   off    0.0
...
Total Power Available:  370 W
Total Power Used:       40 W
Total Power Remaining:  330 W
```

**Note:** If remaining power is insufficient, new PoE devices may fail to power up or the switch may shut down lower‑priority ports.

#### Key Takeaways

| Takeaway | Explanation |
| :--- | :--- |
| **CLI commands are similar across vendors** | Learning one (e.g., Cisco) gives you a strong foundation for others (HPE, Juniper, Arista). |
| **`show mac-address-table` reveals what the switch has learned** | Missing MAC address → unicast flooding. |
| **`show route` shows how a router will forward traffic** | No route → packet dropped. |
| **`show interface` shows link status and errors** | Increasing CRC errors → cable/duplex problem. |
| **`show running-config` is the live configuration** | Changes are temporary until saved to startup‑config. |
| **`show vlan` shows access port membership** | Wrong VLAN = no layer‑2 communication with other VLANs. |
| **`show power` monitors PoE budget** | Over‑subscribing the power budget causes devices to fail. |
